# 集群资源看板（cluster-resource-dashboard）

基于 FastAPI 的集群资源看板服务：从**本地可复现数据源**接入资源快照与变更事件，
对外提供始终自洽的资源视图、按授权范围过滤的查询，以及多订阅者实时推送。
不依赖真实集群或外部网络，相同配置下测试结果稳定可复现。

## 快速开始

```bash
uv run python main.py          # 启动服务（127.0.0.1:8000）
uv run pytest                  # 运行全部自动化测试
```

## API 一览

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/resources` | 列出资源：过滤 / 分页 / 排序 |
| `GET /api/v1/resources/{namespace}/{name}` | 查询单个资源 |
| `GET /api/v1/watch`（WebSocket） | 连续读取实时事件，可携带 `since_rv` |

### 列表参数

- `namespaces`：逗号分隔的命名空间过滤（显式请求越权命名空间返回 403）
- `kind` / `status`：按类型 / 状态过滤
- `sort`：`namespace`（默认）/ `name` / `kind` / `status`；`order`：`asc` / `desc`
- `page` / `page_size`：分页（`page_size` 上限 500）
- 响应含 `items`、`total`、`rv`（本次视图对应的资源版本）

### 鉴权

本地可复现的调用方标识，不依赖外部系统：

- 请求头 `X-Subject`：调用方标识（缺省 `anonymous`）
- 请求头 `X-Namespaces`：逗号分隔的授权命名空间；**缺省表示管理员（全部可见）**

越权语义：

- 单资源查询越权返回 **403**；
- 列表 / 分页 / `total` 计数均在授权过滤**之后**计算，
  任何接口、分页边界或聚合结果都不会泄露被隐藏资源的存在或数量。

### 实时监听（WebSocket）

```
GET /api/v1/watch?since_rv=<rv>
```

- 服务端先补发 `rv` 之后的存量事件，再无缝切换为实时推送，**切换无断层**；
  补发段与实时段重叠的事件按 `rv` 去重。
- 每条事件：`{type, namespace, name, rv, resource}`，
  `type ∈ {ADDED, MODIFIED, DELETED}`。
- 事件同样按调用方授权范围过滤，越权资源的事件不会下发。
- 关闭码：
  - `4100`：**资源版本过期**（`since_rv` 已被压缩），客户端必须重新对齐
    （重新 `GET /resources` 取快照与新 `rv`，再重新监听）；
  - `4101`：订阅积压超限被断开（慢订阅者保护），客户端同样需要重新对齐。

## 视图一致性语义

1. **资源版本（rv）**：全局单调递增。每次真实变更使 rv +1 并追加一条历史事件；
   任意响应中的 `rv` 标识该视图对应的版本。
2. **幂等与乱序**：每条事件携带源端为该资源分配的单调序号 `seq`。
   重复投递与乱序到达的旧事件被丢弃；删除以墓碑记录序号，
   迟到的旧事件不会复活已删除资源。任意投递顺序下，
   最终视图与按序应用（等价于从全量快照重建）的结果一致。
3. **快照可复现**：相同 `rv` 与相同查询参数下，列表结果逐条一致、可复现。
4. **父子状态自洽**：父资源状态在**读取时**由子资源状态派生
   （取子级中最差状态：Failed > Degraded > Unknown > Healthy），
   多级层级自底向上逐层派生，任一时刻读取到的父子状态不自相矛盾。
5. **连续读取**：`list` 响应中的 `rv` 可直接作为 `watch` 的 `since_rv`，
   列表与监听之间不会出现事件断层；rv 过期时必须重新对齐，
   服务端不会返回不一致的结果。
6. **订阅者隔离**：每个订阅者有独立的有界队列，进度互不影响；
   慢订阅者积压超限后被断开（关闭码 4101），不会阻塞其他订阅者、
   数据源或抬高整体延迟。

## 可配置项（`dashboard.app.DashboardConfig`）

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `seed` | 42 | 数据源随机种子；相同 seed 生成完全相同的快照与事件流 |
| `namespaces` | 3 | 生成的命名空间数量 |
| `parents_per_ns` | 2 | 每个命名空间的父资源（App）数量 |
| `children_per_parent` | 3 | 每个父资源的子资源（Pod）数量 |
| `num_events` | 50 | 启动后回放的事件总数（0 表示不回放） |
| `event_interval` | 0.2 | 事件回放间隔（秒），0 表示尽快 |
| `max_history` | 1024 | 事件历史保留条数；超出后旧 rv 被压缩，请求过期版本返回 4100 |
| `max_queue_per_subscriber` | 256 | 单订阅者缓冲队列上限；积满即断开该订阅者 |

## 代码结构

```
dashboard/
  models.py   # 资源 / 事件 / 版本等核心类型
  store.py    # 版本化存储：幂等、抗乱序、墓碑、rv 压缩
  derive.py   # 父级状态派生（读取时计算，保证层级自洽）
  source.py   # 本地确定性数据源（快照 + 事件流）
  auth.py     # 授权范围与越权拒绝
  hub.py      # 订阅中枢：扇出与慢订阅者隔离
  service.py  # 查询、连续读取（补发 + 实时无缝切换）
  api.py      # HTTP / WebSocket 接口
  app.py      # 配置与装配
tests/        # 越权、乱序/重复、rv 过期、慢订阅者、重连等场景
```

## 测试覆盖

- **越权访问**：单资源 403、显式越权命名空间 403、翻页/计数不泄露；
- **乱序与重复**：多种子随机乱序 + 重复投递后视图与按序重建逐条一致；
- **资源版本过期**：`list_events` / `watch` 均触发重新对齐（关闭码 4100）；
- **慢订阅者**：积压被隔离断开，快订阅者不丢事件、不被阻塞；
- **重连**：携带最后 rv 重连后事件连续、无断层、无重复；
- **确定性**：相同 seed 的快照与事件流逐条一致。
